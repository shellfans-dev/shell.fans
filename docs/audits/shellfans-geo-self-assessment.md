## 一、GEO 評估與策略制定

### 1.1 AI 目前怎麼描述 ShellFans

四道已指名品牌的題目、兩個平台，共 8 筆回答。

**AI 認識 ShellFans，但認識的是「社群備份公司」，不是 AEO/GEO 服務商。**

| 題目 | 平台 | 有沒有提到 AEO/GEO |
|---|---|---|
| ShellFans 提供哪些服務？ | Anthropic | ❌ 完全沒提，全篇只講社群資產備份 |
| ShellFans 提供哪些服務？ | OpenAI | ⚠️ 有提，但排在 6 項服務的**最後一項** |
| ShellFans 是什麼公司？ | Anthropic | ❌ 沒提 |
| ShellFans 是什麼公司？ | OpenAI | ❌ 沒提（只講續航引擎） |

這是品牌定位層面的問題，不是技術問題。我們在 AI 眼中的主要身分是社群備份，
AEO/GEO 是附註。

### 1.2 明確的事實錯誤

| 錯誤 | 出處 | 實際情況 |
|---|---|---|
| 支援 **YouTube** | Anthropic「是什麼公司」 | 不支援 |
| 涵蓋 **Twitter、小紅書** | Anthropic「唄粉智能科技」 | 不支援（X 為即將支援） |
| 成立於 **2023 年** | OpenAI，引用自 LinkedIn | **需人工確認**是否正確 |

### 1.3 兩個實體辨識失敗

**「shell.fans 這個網站是做什麼的？」— Anthropic 完全找不到**

> 「搜尋結果顯示 shell.fans 這個域名沒有出現……根據我的搜尋結果，
> 無法找到關於具體 shell.fans 這個網站的信息」

回答轉而解釋 `.fans` 這個頂級網域是什麼。直接問我們的網域，Claude 答不出來。

**「唄粉智能科技是做什麼的？」— OpenAI 完全找不到，而且誤解成粉體產業**

> 「未能找到名為"唄粉智能科技"的公司……市场上有多家专注于**粉体物料**
> 自动化处理和智能化技术的公司」

然後推薦了浙江兆色科技（自動色粉機）、深圳丰年智达（超細粉體生產線）。
「唄**粉**」的「粉」被理解成粉末。這是法人名稱的實體歧義。

### 1.4 AEO 語意歧義比預期嚴重得多

| 題目 | 平台 | AI 理解成 |
|---|---|---|
| 台灣有哪些 AEO 服務公司？ | OpenAI | **Authorized Economic Operator**（報關行：飛運、捷盛報關） |
| 台灣有哪些 AEO 服務公司？ | Anthropic | **海關 AEO 認證**（基隆關 91 家廠商、長榮國際儲運、茂綸） |
| AEO 顧問怎麼選？ | OpenAI | **American Eagle Outfitters**（美國服飾品牌！） |
| AEO 顧問怎麼選？ | Anthropic | 海關 AEO 認證顧問（SGS、湯森路透） |

全部未指名題的引用網域中，**`aeo.customs.gov.tw`（財政部關務署）以 13 次居冠**。

這驗證了 2026-08-15 對探測題所做的去歧義修改是必要的，且方向正確。

### 1.5 競爭對手確實被引用了，我們沒有

## 二、AI 搜尋語意優化

### 2.1 Q&A 結構實測

| 群組 | 頁數 | H2/H3 | 問句形式 | Q&A 條目 | 每頁 |
|---|---|---|---|---|---|
| AEO 知識叢集（新） | 26 | 175 | 33（19%） | **94** | 3.6 |
| AEO 既有頁 | 4 | 41 | 2（5%） | 21 | 5.2 |
| 產品／一般頁 | 12 | 300 | 100（33%） | 30 | 2.5 |

### 2.2 做得好的部分

**FAQ 問句是真實使用者的問法，不是行銷語言。** 抽樣：

- 「現有的 SEO 廠商可以直接做 AEO 嗎？」
- 「要同時找兩家嗎？」
- 「AEO 服務會不會傷害既有的 SEO 成效？」
- 「哪一個比較重要？」
- 「該先做哪一個？」

這正是這一項要求的形態——自然、完整、可直接被擷取為答案。

### 2.3 缺口：9 個重要頁面完全沒有 Q&A 結構

| 頁面 | 性質 | 影響 |
|---|---|---|
| `index.html` | **首頁** | 最高流量頁沒有任何可擷取的問答 |
| `product.html` | 產品總覽（69 個 H2！） | 內容量大但沒有問答形態 |
| `pricing.html` / `price.html` | 價格 | 「多少錢」是高頻問法，卻無對應 Q&A |
| `endurance.html` | 續航引擎 | 主力產品頁 |
| `support.html`、`helpcenter.html` | 客服／幫助 | 這兩頁本質上就是 FAQ，卻沒有 Q&A 標記 |
| `contact.html`、`co-founder.html` | 聯繫／創辦人 | 影響較小 |
| `aeo-geo/methodology.html` | 方法論 | 「分數怎麼算」是常見問法 |
| `aeo-geo/taiwan-aeo-tools.html` | 工具比較 | 比較型內容適合 Q&A |

### 2.4 用語調整的機會

依這一項的原則（「敏感肌保養品推薦」→「換季皮膚好敏感，適合擦什麼保養品？」），
產品頁的用語偏向內部術語，缺少使用者真實問法：

| 現有用語 | 使用者可能的問法 |
|---|---|
| 續航引擎 | 「粉專被停權，貼文救得回來嗎？」 |
| 跨平台社群資產備份 | 「IG 帳號被盜，之前的貼文還在嗎？」 |
| AEO/GEO 代管 | 「怎麼讓 ChatGPT 回答時提到我的品牌？」 |

「續航引擎」是自創詞，沒有人會這樣搜尋。它可以是產品名，
但不該是使用者理解該功能的唯一入口。

## 三、網站結構設計

### 3.1 實測結果（44 頁）

| 項目 | 達成 | 比例 |
|---|---|---|
| main 內恰好 1 個 H1 | 39/44 | 89% |
| 有 H2 階層 | 40/44 | 91% |
| 有 H3 次階層 | 28/44 | 64% |
| 有 FAQ 區塊 | 31/44 | 70% |
| 有 FAQPage schema | 30/44 | 68% |
| 有 Organization schema | 41/44 | 93% |
| 有 BreadcrumbList | 30/44 | 68% |
| **完全無 Schema** | **0/44** | **0%** ✅ |

### 3.2 具體問題

| 問題 | 頁面 | 說明 |
|---|---|---|
| **完全沒有 H1** | `privacy-policy.html`、`terms-and-conditions.html` | 全頁找不到 `<h1>`，只有 `<title>` |
| **H1 是錯字＋不成標題** | `helpcenter.html` | H1 是「**仍有疑問麻?**」——「麻」應為「嗎」，且那是頁尾 CTA 被當成頁面主標題 |
| **標題階層斷裂** | `helpcenter.html` | 0 個 H2 卻有 84 個 H3，H3 沒有父層 |
| **扁平無次階層** | `product.html`（69 H2／0 H3）、`support.html`（27 H2／0 H3） | 大量同層標題，AI 難以判斷主從關係 |
| **FAQ 與 schema 不一致** | `fans-analysis.html` | 有 5 條 FAQ 文案卻無 FAQPage schema——這正是我們自己的 checker 會扣分的項目 |

### 3.3 主題分類

sitemap 44 條，16 條為一層（`/pricing`）、28 條為兩層（`/aeo/what-is-aeo`）。

AEO 叢集有清楚的 hub → child 結構與 BreadcrumbList；
產品線（續航引擎／粉絲分析／社群備份）則是平行的一層網址，
彼此沒有 hub，也沒有 BreadcrumbList。

### 3.4 評分

| 群組 | 評價 |
|---|---|
| **AEO 知識叢集（26 頁）** | ✅ 模範。1 H1、H2/H3 階層、每頁 3–4 條 FAQ + FAQPage、Organization + BreadcrumbList 齊備 |
| **AEO 既有頁（4 頁）** | 🟡 結構良好但方法論頁與工具比較頁缺 Q&A |
| **產品／一般頁（12 頁）** | 🔴 最弱。缺 H1、階層斷裂、幾乎無 Q&A、無 BreadcrumbList |
