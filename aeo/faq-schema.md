# FAQ Schema 怎麼寫？

FAQPage 是 AEO 中投報率最高的結構化資料類型，原因很簡單：答案引擎要找的就是「問題—答案」這個形狀，而 FAQ 天然就是這個形狀。但前提是 **schema 標註的問答必須與頁面上實際可見的內容完全一致**，否則不但無效，還可能被視為操弄。

## 為什麼 FAQ 特別有效

答案引擎在處理內容時，最理想的材料是「一個明確的問題 + 一段自足的回答」。一般文章需要模型自己判斷哪一段在回答什麼；FAQ 則是直接把這個對應關係標示出來。

這也是為什麼 FAQ 段落經常成為被引用的部分——它省去了模型猜測的步驟。

## 問題怎麼挑

### 用使用者真的會問的說法

「本服務之計費機制為何」不是使用者會打的字。「AEO 一個月要多少錢」才是。問題的措辭應該貼近實際查詢，而不是內部術語。

### 一個問題只回答一件事

把三個問題塞進一個答案，會讓這段變得無法單獨引用。寧可拆成三組。

### 答案要能脫離上下文成立

答案中不要出現「如上所述」「詳見上一節」。被擷取出來時，那些指涉全部失效。

### 誠實回答，包括負面的

「這個服務適合誰」之外，也要有「不適合誰」。後者往往更容易被引用，因為使用者實際上很常問「我這種情況適不適用」。

## 實作要點

- 使用 JSON-LD，型別為 `FAQPage`，內含 `mainEntity` 陣列。
- 每個項目型別為 `Question`，其 `acceptedAnswer` 型別為 `Answer`。
- **答案文字應與頁面上可見的文字一致**。若頁面用 HTML 呈現，schema 中放去除標籤的純文字版本。
- 頁面上的 FAQ 建議用 `<details>/<summary>` 或標題結構呈現，讓人與機器讀到相同內容。

> **最常見的錯誤：**schema 裡有十個問答，頁面上只顯示三個。這種不一致沒有好處——搜尋引擎與答案引擎都會比對可見內容，且這種做法在搜尋引擎的政策上通常被歸類為不當標記。

## 其他常見錯誤

- **把行銷文案寫進答案**。「我們擁有業界最強的團隊」不回答任何問題，也不會被引用。
- **問題全部都是自己想推的**。FAQ 的價值來自它回答真實疑問，不是產品介紹的變形。
- **答案太短**。一句話的答案通常缺乏可引用的資訊量，建議 2–4 句並包含具體條件。
- **每一頁都放同一組 FAQ**。重複內容會稀釋訊號，應該讓每頁的 FAQ 對應該頁主題。

## 常見問題

### FAQ schema 標的問答一定要顯示在頁面上嗎？

是。schema 是可見內容的機器可讀版本，不是額外欄位。標註了但頁面上看不到的問答，屬於不一致標記，不會帶來好處。

### 一頁可以放幾個問答？

沒有硬性限制，但建議聚焦。五到十組切題的問答，勝過二十組泛泛而談。重點是每一組都要對應該頁的主題。

### FAQ 要放在頁面哪個位置？

通常放在主要內容之後、頁尾之前。位置本身不是關鍵，重要的是內容可見、可被爬蟲讀取，且不需要點擊或互動才會出現。

### 用 details/summary 摺疊起來會影響擷取嗎？

不會。details/summary 的內容存在於 HTML 原始碼中，爬蟲可以讀取。真正有問題的是需要 JavaScript 執行後才載入的內容。
